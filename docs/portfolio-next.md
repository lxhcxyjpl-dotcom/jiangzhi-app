# 作品展示与产品对照：下一步清单

范围：对照项目外的《一个奇怪的自律方法：主动降智》，依据 README、`app/index.html` 与 `main.js` 静态审计；不是方法有效性验证，也不是界面实测结论。排序按影响／成本综合判断；Luna 适合文案和简单整理，Terra 适合实现与验证，Sol 适合涉及交互取舍的综合设计。以下均为建议，尚未实施。

## 方法链对照

状态表示产品支持程度，不代表用户实际完成了该行为。

| 环节 | 状态 | 现状与缺口 |
| --- | --- | --- |
| 规划 | 已实现 | 阶段任务、执行点、完成标准和最晚检查分钟数可手写；AI 可选起草并由用户确认。可行动性仍由用户判断。 |
| 环境预设 | 半实现 | AI 草稿可编辑环境建议并存入任务的 `setupHint`，但未找到后续展示或手动编辑入口；日历可挂日期，不等于情境触发或环境已就位。 |
| 预制叙事 | 已实现 | 内置及自写提示语，可关联任务、切换或隐藏；专注时也显示同任务已标记的证据。 |
| 第一小步 | 半实现 | 执行点鼓励写可直接动手的动作；启动失败前提示完成打开、读、尝试的单元，但没有独立的动态第一步引导，也无法判断实际动作。 |
| 对象层专注 | 半实现 | 专注页保留当前执行点、提示语、计时与退出入口，减少界面选择；没有针对任务内容的对象层锚点或“检查点再讨论”的专门入口。 |
| 任务内反馈 | 缺失 | 产品不能观察任务内部真实反馈；结束三问和证据是事后记录，不应等同于执行中的反馈。文章也不要求每一步弹窗表扬。 |
| 检查点三问 | 半实现 | 可提前手动结束并回答新信息、进展／卡点、下一步；可新建下一执行点。到点只通知并进入超时，明确允许结束时再回答，不能保证最晚检查；保存时无论卡住或提前中断，当前执行点均标为完成。空进展默认“有推进”，也可被标为证据。 |
| 大复盘与证据 | 半实现 | 每日两问、随手记、手动标证据、证据星空及回顾统计可用；可选 AI 周回顾，但缺少明确的人工战略判断／调整闭环。投入时长不是能力证据；AI 提示要求不编造，不能保证输出真实。 |
| 中断与恢复边界 | 半实现 | 可放弃或在确认尝试后记录启动失败，并提示休息；没有明确说明身体异常、安全风险及前提错误可立即中断，也没有结构化冷静期。 |

调度核对：前端 250ms tick 触发到点提示和超时状态；手动结束时 `actualEnd` 被限制在计划结束时间，统计可能漏掉超时，尽管回顾文案声称含超时。恢复已过期会话时直接置超时，不补发提示。桌面每日提醒由 `main.js` 每 30 秒检查本地时分，应用运行且匹配该分钟才触发；浏览器依赖页面运行和通知权限，均不保证错过后的补发。

## 展示向 README + 演示体验（优先顺序）

1. **重写 README 首屏与体验路径**（高影响／低成本；Luna）。文件：`README.md`。验收：首屏说明定位、方法链、桌面／浏览器入口及无 Key 可用范围；提供一条从新建执行点到三问、证据回顾的短路径；修正项目外 `outputs/` 的失效来源表述和“AI 只起草清单”与 AI 周回顾的矛盾；保留原文不入库。
2. **做真实界面演示素材**（高影响／中成本；Terra）。文件：`README.md`、经确认可公开的 `docs/` 截图或短动图。验收：在实际运行环境录制清单→专注→三问→证据星空，使用虚构内容、无 Key；README 可直接看到素材并注明平台与录制日期，不声称未经验收的安装包可用。
3. **写可复现的无 Key 演示脚本**（中高影响／低成本；Luna）。文件：`README.md`。验收：从干净浏览器数据或隔离桌面用户数据出发，列出示例输入、点击和预期结果；明确手动输入虚构数据；现有 `loadDemo` 未发现界面入口，不依赖它，并提醒勿覆盖个人数据；能在不等待长计时、不调用 AI 的情况下走通。
4. **整理运行与数据边界**（中影响／低成本；Luna）。文件：`README.md`。验收：区分 `npm test`、会创建窗口的 Electron SMOKE、实际人工验收；注明浏览器跨域／通知限制、Key 存储差异及历史备份风险；不把计划中的功能写成现状。

## 小而可验证的产品优化（优先顺序）

1. **保留未完成的执行点**（高影响／中成本；Terra）。文件：`app/index.html`、适当的行为测试文件。验收：三问保存时明确由用户选择完成或保留；卡住、分心和中断不会自动完成；选择完成与新建下一步仍正常，主窗／组件窗一致。
2. **证据必须来自明确填写的事实**（高影响／低成本；Terra）。文件：`app/index.html`、必要的行为测试文件。验收：空进展可以保存会话，但不能把默认“有推进”直接存为证据；填写具体进展后可标记，已有证据不被改写。
3. **修正超时时长记录**（中高影响／低成本；Terra）。文件：`app/index.html`、必要的行为测试文件。验收：例如计划 1 分钟、实际 2 分钟后结束，记录和统计使用真实结束时间；提前结束仍正确，既有记录不被批量改写。
4. **让环境建议可见**（中影响／低成本；Terra）。文件：`app/index.html`。验收：已有 AI 生成的 `setupHint` 在对应任务卡可见；空值不显示，无需接入 AI 即可查看已有内容。
5. **补充即时中断边界**（中影响／低成本；Luna）。文件：`app/index.html`。验收：专注界面或紧邻退出入口简洁说明身体异常、安全风险、任务前提错误可以立即停止；现有退出和失败记录保持可用，不强迫等待检查点。

## 需要人类拍板的大决策

- **检查点强度**：到点强制进入三问、只提醒并允许继续，还是提供轻量检查／延后？这影响沉浸体验和文章“最晚检查”的解释；先确认再设计，不将强制检查纳入上述小改。
- **产品定位与演示承诺**：主推单 HTML 免安装、Electron 桌面组件，还是双入口并列？决定首屏、素材、支持平台及后续发布投入；Windows 安装包尚未验收。
- **AI 与隐私边界**：是否保留周回顾、发送哪些记录、如何呈现第三方处理及生成内容的不确定性？涉及功能定位与数据使用，不默认扩展 AI。
- **复盘深度和恢复机制**：是否增加战略决策、跨周实验追踪、冷静期或自动提醒？这些会扩大产品模型，先由人确定目标与负担。
- **原文公开引用方式**：仓库外原文是否有可公开且获授权的链接或引用方式，由人确认；在此之前只描述方法来源，不复制原文进仓库。
